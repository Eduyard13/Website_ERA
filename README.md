# ERA — прототип сайта

Версия 0.3.0: презентационная главная по материалам ERA, подробное описание трёх стадий технологии и управления, реестр 12 узлов, каркас комплектаций и галерея. Русский язык, адаптивная вёрстка, статические HTML-страницы без внешних зависимостей.

## Запуск

Требуется Node.js 22 или новее. Установка npm-пакетов не нужна.

```sh
cd /workspace/Website_ERA
npm run dev
```

Сервер слушает порт 3000. Другой порт: `PORT=3001 npm run dev`. Процесс необходимо запускать заново после восстановления облачной среды.

```sh
npm run build
npm test
```

Сборка создаётся в `dist/`. Для статического хостинга нужны поддержка `index.html` в каталогах и выдача `404.html` с HTTP-статусом 404. `npm run dev` и `npm start` собирают сайт при запуске. После изменения шаблонов или контента повторите сборку; после изменения файлов public повторите сборку. Автоматического обновления в браузере пока нет.

## Устройство

- `content/site.mjs` — общие разделы, стадии и структурированные параметры узла.
- `scripts/build.mjs` — шаблоны и генератор 30 страниц.
- `public/style.css` — адаптивный стиль, 360 / 768 / 1440 px.
- `public/app.js` — мобильное меню и раскрывающаяся навигация.
- `scripts/server.mjs` — сервер для локальной разработки.
- `test/site.test.mjs` — проверка внутренних ресурсов и якорей всех страниц, условий технических показателей.

Существующий checkout использовать напрямую; отдельный worktree не нужен.

## Источники и ограничения

Структура и тексты основаны на `ERA_Website_Brief_for_Codex.md`. Изображения, логотип и параметры измельчителя извлечены из предоставленного `КП_Пре-Шредер_(дробилка).pdf`. Изображение базового узла — визуализация; фотографии сборки подписаны отдельно. Контакты взяты из того же КП и требуют проверки перед публикацией. Производительность по плёнке — 1500–3000 кг/ч; диапазон других полимеров — 3000–7000 кг/ч; потребляемая мощность 33,04 кВт — расчёт, а не измерение.

Исходный PDF не опубликован, так как публичная редакция не согласована. Документы, реквизиты, новости, блог, описание функций управления и ИИ показывают пустые состояния. Направления линий не представлены как готовые серийные продукты.

Это прототип для согласования. Включены `noindex,nofollow` и запрет индексации в robots.txt; это не ограничение доступа. Перед открытым размещением требуется согласовать контент и права публикации материалов, контакты и юридические документы. Для закрытого просмотра используйте средства доступа хостинга.

CMS, роли, черновики, серверные заявки и закрытые файлы ещё не реализованы. Кнопки обращения открывают почтовую программу; уведомлений об успешной отправке нет. Почта/CRM, аналитика, домен и инфраструктура не подключены. Публичный запуск требует отдельной проверки и подключения этих функций.

## Версии и тестовое размещение

Версии хранятся в GitHub-коммитах. Первая версия отмечена тегом `v0.1.0`. Последующие согласованные этапы можно отмечать следующими тегами, сохраняя историю без перезаписи. Откат выполняется отдельным коммитом, чтобы не терять более позднюю работу.

В `.github/workflows/pages.yml` настроены проверки и публикация GitHub Pages из ветки `main`. В настройках репозитория **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**. Если первый запуск уже завершился ошибкой до включения Pages, повторите его через **Actions → Test and deploy ERA preview → Run workflow**. Фактический адрес появляется в успешном шаге Deploy preview и в Settings → Pages. Доступность Pages зависит от настроек и тарифа репозитория. Приватный репозиторий сам по себе не делает опубликованный Pages-сайт закрытым.

Сборка для стандартного адреса проекта:

```sh
BASE_PATH=/Website_ERA npm test
BASE_PATH=/Website_ERA npm run build
```

`BASE_PATH` добавляет префикс ко всем внутренним ссылкам и ресурсам, включая страницу 404. Для корневого адреса или собственного домена оставляйте BASE_PATH пустым и обновите соответствующее значение в workflow. `npm run dev` по умолчанию использует корневую структуру.

Pages подходит для этого статического прототипа. Для CMS и серверной обработки заявок потребуется отдельное решение по размещению. Запрет индексации не закрывает доступ по ссылке.


## Обновление по брифу 2.0

Актуальное задание: `docs/ERA_Website_Brief_v2.md`. Палитра задана общими CSS-переменными `--era-*`: #102B46, #F7F4EE, #C6A43B. Используется Arial с кириллицей; оригинальные пропорции логотипа сохранены.

`content/catalog.mjs` — единый реестр 12 узлов, связанное медиа и 4 проекта комплектаций. Две сепарационные и одна моечная включены по умолчанию. `enabled: false` у третьей сепарационной делает её дополнительной; интерфейс позволяет посмотреть и вариант с четырьмя. При переключении enabled шаблон менять не нужно. Ни один проект комплектации не обозначен как согласованное предложение.

Фильтры каталога, линий и галереи хранят состояние в URL. Галерея содержит 3 фотографии, схему и визуализацию из КП. Видео не предоставлены. Просмотрщик поддерживает Escape, стрелки, явное закрытие и возврат фокуса. Ссылки и адреса изображений в data-атрибутах тоже учитывают BASE_PATH.

Для проверки схемы Pages локально:

```sh
BASE_PATH=/Website_ERA PORT=3001 npm run dev
```

Сервер обслуживает заданный базовый путь и позволяет проверять прямое открытие вложенных страниц. При изменении источников нужна повторная сборка с тем же BASE_PATH. Не запускайте одновременные сборки: они записывают один каталог dist.

В репозитории фактически нет технических материалов остальных 11 узлов, согласованных схем линий, видео, визуального эскиза и отдельного era-theme.css. Упоминание файлов в задании не считается их получением. Для недостающих материалов показан явный статус подготовки без придуманных параметров и изображений. Документы по-прежнему не опубликованы для скачивания; исходное КП не названо паспортом. CMS и серверные формы остаются следующим этапом.


## Презентационная главная — 0.3.0

Главная рассказывает о проекте по цепочке: предложение → сырьё и загрязнения → сухая сепарация, горячая отмывка, грануляция → результат → управление → путь реализации → подробные разделы → обращение. Реестр черновых карточек, технические таблицы и пустые публикации находятся на внутренних страницах.

- `content/presentation.mjs` — редакционные данные трёх стадий, результатов, этапов проекта и медиаматериалов с источниками.
- `scripts/home.mjs` — презентационная главная, подробная технология и описание управления.
- `public/presentation.css` — стили этих страниц, изолированные классом `.story`.
- `public/assets/presentation/` — веб-копии встроенных изображений предоставленной презентации. Исходный PDF целиком в публичный сайт не включён.

Изображения извлечены из PDF с сохранением цветов, пропорций и исходной прозрачности. Иллюстрации стадий не обозначены одной серией испытаний; чертежи компоновок не назначены автоматически конкретным вариантам каталога. Источники и редакционные решения перечислены в `docs/presentation-notes.md`.

По явному выбору заказчика сохранены действующие телефон и почта из прежнего КП. Контакты с последнего слайда презентации не перенесены. Кнопки открывают почтовую программу; промышленное управление и серверная отправка заявок в состав сайта не входят.

Версия ресурсов CSS/JS берётся из package.json, а srcset учитывает BASE_PATH. Изменение версии позволяет получить новые стили при обновлении сайта. При проверке префикса публикации выполняются также проверки всех кандидатов srcset.

Для браузерной проверки можно запустить сайт с BASE_PATH=/Website_ERA и PORT=3002, затем `python3 test/presentation.browser.py` в среде с установленными Playwright и Chromium. Адрес и каталог скриншотов переопределяются через ERA_PREVIEW_URL и ERA_SCREENSHOT_DIR. Это дополнительная проверка; GitHub Actions запускает npm test и сборку.
