# ERA — сайт проекта

Версия 0.5.0: презентационная главная, карточки 12 узлов с ключевыми параметрами и нумерованными схемами, 65 фотографий из архивов заказчика, фотогалерея по оборудованию и исходные PDF. Статический многостраничный сайт на русском языке без внешних npm-зависимостей.

## Запуск и сборка

Требуется Node.js 22 или новее. Установка npm-пакетов не нужна.

```sh
cd /workspace/Website_ERA
npm run dev
```

Сервер слушает порт 3000. Можно указать другой: `PORT=3001 npm run dev`. При восстановлении облачной среды процесс запускают заново. Используйте существующий checkout; отдельный Git worktree не требуется.

```sh
npm run build
npm test
```

Результат сборки — `dist/`, 30 HTML-страниц, изображения, CSS/JS и документы. Сервер разработки выполняет сборку при запуске. После правок нужно снова выполнить сборку и обновить браузер; автоматического обновления пока нет. Не запускайте одновременные сборки: они записывают один каталог.

## GitHub Pages и версии

Публикация настроена через `.github/workflows/pages.yml` после обновления ветки `main`. В GitHub **Settings → Pages → Source** должен быть выбран **GitHub Actions**. Ручной запуск доступен через **Actions → Test and deploy ERA preview → Run workflow**.

Адрес проекта: https://eduyard13.github.io/Website_ERA/.

```sh
BASE_PATH=/Website_ERA npm test
BASE_PATH=/Website_ERA npm run build
```

Для проверки той же структуры локально:

```sh
BASE_PATH=/Website_ERA PORT=3003 npm run dev
```

BASE_PATH применяется к ссылкам, изображениям, srcset, PDF, адресам в data-атрибутах и странице 404. На статическом хостинге нужны поддержка index.html в каталогах и выдача 404.html с правильным статусом. Для размещения в корне или на своём домене BASE_PATH оставляют пустым и меняют соответствующее значение в workflow.

Согласованные этапы сохранены тегами v0.1.0–v0.5.0. История описана в CHANGELOG.md. Откат выполняйте отдельным коммитом, сохраняя последующую историю. Версия CSS/JS берётся из package.json для обновления кэшированных ресурсов.

## Контент и шаблоны

- `content/site.mjs` — основные разделы, базовые данные предварительного измельчителя.
- `content/catalog.mjs` — реестр 12 узлов, категории, 4 проекта комплектаций и объединённая медиатека.
- `content/equipment-details.mjs` — параметры каждого узла, условия подачи, процесс, конструкция, комплект поставки, примечания и связанные узлы.
- `content/document-manifest.mjs` — исходные документы: тип, имя, размер, число страниц и SHA-256.
- `content/equipment-media.mjs` — изображения из КП с типом, страницей и названием источника; отдельная функциональная схема роторного распушителя.
- `content/customer-photos.mjs` — 65 обработанных фотографий: узел, подпись, тема, главный кадр, оригинальное имя и SHA-256, размеры веб-копии и миниатюры.
- `content/equipment-reading.mjs` — выбор шести основных характеристик из полной таблицы и расшифровка номеров схем.
- `content/equipment-videos.mjs` — готовые и ожидающие источника видеопрезентации; в публичные страницы включаются только записи ready:true.
- `content/presentation.mjs` — история проекта, три стадии и медиа из презентации.
- `scripts/build.mjs` — сборка, общая оболочка страниц и базовый путь.
- `scripts/navigation.mjs` — общая навигация, точная текущая страница и родительский раздел.
- `scripts/equipment.mjs` — единый шаблон всех карточек и раздел документации.
- `scripts/media.mjs` — сетка медиа с миниатюрами и доступный просмотрщик полных изображений.
- `scripts/gallery.mjs` — фотогалерея, подборки по оборудованию и фильтры типов материалов.
- `scripts/video.mjs` — необязательный киноблок карточки узла.
- `scripts/static-server.mjs` — локальная потоковая выдача файлов, MIME видео и диапазоны байтов для перемотки.
- `scripts/home.mjs` — главная, подробная технология и управление.
- `scripts/views.mjs` — каталог, комплектации и остальные страницы.
- `public/style.css`, `public/equipment.css`, `public/presentation.css` — общие стили, оборудование и презентационные страницы.
- `public/app.js`, `public/interactions.js` — меню и фильтры; `public/media-viewer.js` — общий просмотрщик фотографий и видео.

Контент редактируется в файлах данных; CMS пока не подключена. После изменения данных нужна новая сборка. Фильтры хранят состояние в URL и восстанавливаются при возврате. Новые документы доступны как в карточке узла, так и в разделе «Документация» с поиском и фильтрами.

## Источники и точность

Сайт основан на брифе 2.0, презентации ERA и 12 предоставленных продуктовых документах. Веб-копии изображений извлечены из PDF с сохранением геометрии, исходных цветов и масок прозрачности. Для векторных схем использован рендер исходного фрагмента страницы. Чертежи конструкции не перерисовывались. Для роторного распушителя добавлена отдельно обозначенная функциональная схема трёх стадий по описанию КП.

Из 11 архивов заказчика добавлено 65 обработанных фотографий. Веб-копии WebP имеют до 1920 пикселей по большей стороне, миниатюры — до 800; увеличения исходного разрешения нет. Миниатюры загружаются отложенно, полный файл открывается в просмотрщике. Изображения каталога сохранены; главные фото карточек выбираются независимо. Номера и подписи исходников сохранены в реестре. Общий размер новых изображений с миниатюрами — около 20,3 МБ; галерея не скачивает все полные изображения при открытии.

Для комплекса очистки стоков архив фотографий пока не предоставлен: используются схемы и кадры из PDF. Архив «Предварительный измельчитель» сопоставлен с предварительным распушителем по конструкции и фотографиям из его КП; пре-шредер загружен отдельно.

Исходные PDF в `public/documents/` сохранены без изменений. Это 10 коммерческих предложений и 2 смешанных документа: паспорт с коммерческим описанием рамы-наполнителя и паспорт с коммерческим предложением бункера. Наличие паспорта в комплекте поставки не означает наличие отдельного PDF-паспорта на сайте. Размер каждого файла указан рядом со скачиванием. Около 72 МБ документов не загружаются при обычном открытии страницы; загрузка происходит по действию пользователя.

Установленная, расчётная и фактическая потребляемая мощность различаются. Там, где расчёт не дан, значение не вычислялось автоматически. Объёмная подача сепаратора в м³/ч, ёмкость бункера в м³ и массовая подача полимеров не смешиваются. Целевые показатели влажности сопровождаются условиями подтверждения на согласованном сырье.

Капсулятор по последнему КП описан как отжимной пресс, не как гранулятор. Компоновки из презентации не назначены автоматически конкретным комплектациям линий. Две сепарационные и одна моечная запись включены по умолчанию; третья сепарационная управляется данными и переключателем. Их состав и параметры ещё требуют спецификаций.

В медиатеке различаются фото, визуализации, схемы и кадры из видео. Кадр из PDF не считается загруженным видеороликом. Тип изображений из КП центрифуги и флотатора сохранён по оговоркам источников; новые изображения из архивов подписаны как обработанные фотографии. Подключение первого ролика ожидает получения исходного файла в рабочую среду.

Подробные редакционные решения: `docs/presentation-notes.md` и `docs/equipment-sources.md` и `docs/photo-sources.md`. Сохранённый бриф — `docs/ERA_Website_Brief_v2.md`.

## Проверки

`npm test` проверяет внутренние маршруты и ресурсы всех страниц, srcset и базовый путь, параметры, различия единиц, 12 PDF и их контрольные суммы, активное состояние навигации, соответствие фотографий узлам, миниатюры, сохранение иллюстраций каталога и отсутствие выдуманной потребляемой мощности. Workflow выполняет проверки для корня и /Website_ERA/.

Дополнительные браузерные проверки требуют Python, Playwright и Chromium:

```sh
python3 test/presentation.browser.py
python3 test/equipment.browser.py
python3 test/media.browser.py
```

Презентационный сценарий по умолчанию ожидает сервер на порту 3002, оборудования — на 3003, галереи — на 3004; все с BASE_PATH=/Website_ERA. Адрес и каталог скриншотов переопределяются через ERA_PREVIEW_URL и ERA_SCREENSHOT_DIR. Браузерные сценарии не входят в npm-зависимости и не запускаются в GitHub Actions.

Подготовка видеоплеера описана в `docs/video-notes.md`. Команда `python3 test/video.browser.py` дополнительно требует FFmpeg, создаёт изолированный синтетический ролик и проверяет воспроизведение, перемотку, полноэкранный режим, остановку и ошибки. Тест не публикует ролик и не заменяет проверку исходного видео заказчика. Пока исходник не получен, публичная запись выключена.
