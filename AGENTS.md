# AGENTS.md — постоянный стандарт разработки ЭРА

Этот файл должен находиться в корне репозитория. При наличии действующего AGENTS.md объединить правила, не отменяя более строгие требования безопасности и публикации.

## Архитектура
- Статический многостраничный сайт Node.js; PHP backend Reg.ru отдельно. Не вводить новый стек без согласования.
- `content/` — предметные данные и контент по разделам; `scripts/` — build/render/media/deploy/maintenance; `public/assets/css` и `public/assets/js` — ресурсы браузера по назначению; `public/documents` — публичные PDF; `docs/` — инструкции, архитектура, аудит, история; `test/` — тесты. Поддерживать `docs/architecture/` актуальным.
- Не добавлять CSS/JS/MJS в корень public или dist. Исключения совместимости документировать с обоснованием и сроком/условием удаления. Не создавать временные, old, final-new, backup и подобные копии в public. Новые имена — lowercase kebab-case латиницей; не менять существующие публичные адреса без совместимости.
- Каждый модуль имеет одну ответственность. Общие компоненты используют единый источник. Финансовые параметры и формулы — единое ядро, не дублировать данные в карточках/шаблонах. Сохранять семантику и исходные цифры без прямого задания на финансовое изменение.
- Любой новый ресурс регистрировать в подходящем тематическом каталоге/реестре. Перед добавлением проверить точные дубли; сохранять оригинальные инженерные PDF и изображения нужного качества. Удаление — только с проверкой полного графа зависимостей.
- Сохранять утверждённые визуалы, структуру страниц, SEO URL, якоря, мобильную адаптацию, доступность, legal и API. Динамические функции не заменять статичными макетами.
- Все пути поддерживают preview BASE_PATH=/Website_ERA и production BASE_PATH=''; тестировать обе цели. Обновлять кеш-ключи по изменению файлов, включая зависимости.

## Проверки и публикация
- Перед правками проверить HEAD, незакоммиченные изменения, актуальные инструкции и контекст. Не перезаписывать чужую работу.
- Перед завершением запускать `npm run validate:structure`, сборку и соответствующие тесты; для масштабных правок — полный набор, браузер и регрессия. Команды поддерживать актуальными; валидатор — обязательный CI gate. Не ослаблять тесты для прохождения.
- `dist/` генерируется чистой сборкой, не правится вручную. Не публиковать source/docs/test/node_modules, секреты, архивы, логи и пользовательские данные. Не хранить секреты в публичном Git.
- Reg.ru: серверные файлы, SMTP, конфиг, state, uploads, .htaccess, legal и CBR защищены; не перезаписывать обычным патчем. Проверять актуальный live-манифест, хеши, резервирование и откат. Удаление только отдельно подтверждённых путей, не рекурсивно по произвольным каталогам. Не запускать незапрошенные production-записи.
- Финальный отчёт: SHA, версия, тесты, что изменилось, ограничения, миграция, что нужно владельцу. Не утверждать успешную публикацию без проверки.
