# Архитектура ЭРА 2.0

## Исходники и сборка

| Каталог | Назначение |
|---|---|
| `content/` | Данные сайта по разделам. Экономические данные, каталог, документация, линии, КАИР, юридические тексты |
| `scripts/build/` | Режимы публикации, сборка HTML, реестр URL, проверка структуры и ссылок |
| `scripts/render/` | Шаблоны страниц и общие компоненты |
| `scripts/media/`, `scripts/maintenance/` | Подготовка графики и документов, инструменты локального запуска |
| `scripts/deploy/` | Манифесты, архивы, проверка установки, атомарное обновление и карантин Reg.ru |
| `public/assets/css/`, `public/assets/js/` | Стили и JavaScript по разделам. Общие части в подкаталогах по назначению |
| `public/assets/`, `public/documents/` | Публичные фотографии, инженерные материалы, оригинальные PDF, локальные шрифты и видео |
| `server/regru/` | PHP-обработчик, образцы настроек, обновление ЦБ РФ, приватные компоненты |
| `test/` | Модульные, интеграционные, браузерные проверки, тесты размещения и фиксированные данные |
| `docs/` | Архитектура, эксплуатация, архив, аудиты и инструкции |

На публикацию идут файлы из чистой сборки `dist/`. Она поддерживает корень `https://era-cycle.ru/` и префикс `/Website_ERA` на GitHub Pages. Сборка сохраняет SEO-маршруты, якоря и публичные пути инженерных материалов. Экономическая модель находится в `public/assets/js/economics/`. Контроллер всех четырёх инженерных центров расположен в `public/assets/js/equipment/shared/engineering-center.js`. У линий остаются свои таблицы стилей и реестры ракурсов.

## Ресурсы, кеш и совместимость

`content/shared/browser-assets.json` связывает прежние имена ресурсов с тематическими путями. Сборщик проверяет наличие относительных импортов, CSS-ресурсов и зарегистрированных динамических зависимостей. Версия в URL зависит от SHA-256 содержимого ресурса, путей и транзитивных зависимостей. Инструменты поставки PDF.js и fflate остаются локальными. Их динамические импорты и воркер перечислены в реестре. Источник CSS остаётся читаемым. В сборке CSS проходит через зафиксированный в lock-файле CleanCSS с отключёнными преобразованиями правил.

28 корневых URL собираются из тех же исходников для совместимости с установленными юридическими страницами. В реестре указаны 25 непосредственно используемых файлов и три транзитивных модуля, которые могут запрашивать прежние кешированные скрипты. Два защищённых HTML-файла и их PDF остаются доступными по прежним путям. Удаление алиаса допустимо после сверки действующих юридических страниц, зависимостей и истечения срока кеширования. Частный серверный комплект, который уже установлен на Reg.ru, обслуживается отдельным процессом.

Лицензионные сведения хранятся вместе с распространёнными библиотеками. Источники иллюстраций описаны в [инструкции](../instructions/brand-assets.md).

## Проверки и миграция

`npm run validate:structure` проверяет исходники. Параметр `-- --dist dist` добавляет проверку ссылок, якорей, регистра, совместимых корневых путей и префикса сборки. Проверка запускается в GitHub Actions перед загрузкой артефактов. Node-тесты проверяют ревизии зависимостей и данные, тесты развёртывания проверяют инкрементальное применение и откат. Интерактивность и визуальный паритет проверяются в Chromium.

Файлы передаются на Reg.ru по манифесту SHA-256. Существующие файлы, отсутствующие в новом релизе, по умолчанию остаются на месте. После проверки установленной версии и отдельного утверждения списка `regru_cleanup.py` переносит подтверждённые старые файлы в закрытый карантин. Повторный запуск проверяет содержимое и пропускает уже обработанные файлы. При откате старые ресурсы возвращаются до публикации прежнего HTML.
