## Форма

Основные файлы: `content/contact.mjs`, `scripts/contact.mjs`, `public/request.js`, `public/request.css`. На обычных страницах форма открывается в нативном `dialog`, на `/contacts#project-form` — находится в основном содержимом. Без JavaScript ссылки ведут к отдельной странице формы.

Обязательные поля: имя, email и описание задачи. Компания, телефон, интересующее решение, ссылки и файлы — необязательные. Ссылки на предложения с прежней темой `mailto:` автоматически ведут к форме и сохраняют контекст. Обычные ссылки с адресом почты оставлены. При отправке добавляются тема письма, страница обращения и список вложений; email клиента предназначен для ответа.

Изображения, видео и PDF выбирают кнопкой или перетаскиванием; файл можно убрать. Размер исходящего вложения ограничен 5 000 000 байтами. В расчёт входят заголовки архива. Большие материалы передают ссылкой. При нескольких файлах браузер собирает стандартный ZIP без сжатия: исходные байты сохраняются, имена записываются в UTF-8, одинаковые имена получают суффикс. В почтовый шлюз уходит один файл в документированном поле `attachment`. При одном файле отправляется оригинал; без JavaScript доступно одно вложение.

Заявка отправляется настоящим `multipart/form-data` POST, а не через почтовую программу. Сохранены стандартная защита FormSubmit от спама и поле-ловушка. Ни пароли, ни ключи почты в клиентском коде не используются. Значения клиента передаются только после нажатия «Отправить заявку». Успех на странице до ответа сервиса не имитируется: возврат на `/contacts/sent/` выполняет сервис после обработки.

## Обязательный запуск приёма писем владельцем

Получатель: **edkom.office@mail.ru**. Приёмник: `https://formsubmit.co/edkom.office@mail.ru`. GitHub Pages размещает статические файлы, поэтому для приёма формы используется внешний сервис [FormSubmit](https://formsubmit.co/).

Подтверждение владения адресом выполняется в почтовом ящике получателя:

1. После публикации открыть `/contacts#project-form` и отправить пробную заявку со своими контактами. Первое обращение к неподтверждённому получателю запускает письмо активации FormSubmit.
2. Открыть это письмо в **edkom.office@mail.ru** и подтвердить адрес. Если адрес уже активирован для сайта, повторное подтверждение может не потребоваться.
3. После активации отправить новую пробную заявку, включая фото, небольшой видеофайл и ссылки. Проверить письмо, тему, контакт клиента и архив материалов.

Статус на момент подготовки версии: **подтверждение получателя и доставка реального письма не проверены**. У этой сессии нет доступа к почтовому ящику и подтверждению адреса. До проверки владельцем нельзя считать приём писем запущенным. Тестовые обращения из браузерных тестов перехватываются локально и не отправляются в рабочую почту.

Настройки приёмника, адреса, лимита и публичного домена находятся в `content/contact.mjs`; `_next` учитывает `BASE_PATH`. Перевод на другой шлюз требует согласования его полей, обработки вложений и возврата, помимо смены endpoint.
