# Видеопрезентации узлов — подготовка

Заказчик поручил сначала подключить ERA_Shredder_Avito_1080p.mp4 к предварительному измельчителю и проверить этот формат перед добавлением других роликов.

## Состояние источника

Перенос вложения не выполнен: download_file отклонил файл из-за лимита 32 МиБ. Заказчик предоставил ссылку Google Drive. Прокси рабочей среды отклонил соединение с drive.google.com; это ограничение сетевой политики, а не подтверждение отсутствия прав на сам файл. Сохранён черновик сетевых разрешений для drive.google.com и drive.usercontent.google.com. Пока он не применён, скачивание, анализ исходного ролика, выбор кадра из него и публикация реального видео не выполнены.

Запись в content/equipment-videos.mjs имеет ready:false. Она не входит в публичную медиатеку и не создаёт пустого видеоблока на странице. Постер в записи пока ссылается на ранее предоставленную фотографию узла, а не на извлечённый кадр. Публичная версия сайта 0.5.0 не обновлялась в рамках этой подготовки.

## Оформление и воспроизведение

Готовый видеоблок располагается после первого экрана и навигации по карточке, перед назначением. В первом экране и навигации появляется переход «Смотреть видео» / «Видео». У узлов без готовых роликов этих элементов нет. Несколько роликов одного узла поддерживаются общей записью медиатеки: первый показан крупно, остальные — дополнительными карточками.

Тёмный экран с постером открывает диалог с затемнением страницы, нативным видеоплеером, звуком, перемоткой, полноэкранным режимом и ссылкой на отдельный файл. MP4 не загружается при открытии страницы: src назначается только после действия пользователя. На мобильных используется playsinline. Закрытие, переход к другому материалу и Escape останавливают воспроизведение и освобождают источник. Фокус возвращается к открывшему элементу. Ошибка источника показывает доступную альтернативу и не блокирует закрытие.

Плеер общий для карточек узлов и вкладки «Видео» галереи. Изображения продолжают открываться в том же просмотрщике. Отдельные кадры из PDF остаются типом frame, а не видео.

Локальный сервер передаёт MP4 как video/mp4 и поддерживает потоковую выдачу, запросы диапазонов байтов (206), HEAD и ответ 416 на недоступный диапазон. Это позволяет проверять перемотку без чтения всего файла сервером в память. Для публикации на GitHub Pages сервер Node не требуется.

## Проверки

npm test проверяет необязательность блока, соответствие страницы узлу, путь GitHub Pages, постеры, безопасные подписи и отсутствие преждевременной загрузки в разметке. test/video.browser.py создаёт синтетический восьмисекундный клип в отдельном временном каталоге и проверяет реальное воспроизведение со звуком, перемотку, полноэкранный режим, остановку и освобождение источника, возврат фокуса, фильтр видео и обработку ошибки на ширинах 360, 768 и 1440. Тестовый клип не попадает в public, Git или опубликованный сайт. Эта проверка не считается проверкой пользовательского исходника.

## Завершение после получения файла

Проверить исходник через ffprobe, просмотреть кадры и звук. Подготовить совместимую веб-копию MP4 H.264/AAC с yuv420p и faststart, не менять содержание без необходимости. Сохранить оригинальное имя, размер, длительность и SHA-256 в реестре. Выбрать постер после просмотра самого ролика. Затем включить ready, обновить версию ресурсов, проверить реальный файл в браузере и только после этого публиковать новую версию сайта.
