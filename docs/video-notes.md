# Видеопрезентации узлов

Заказчик поручил сначала подключить ERA_Shredder_Avito_1080p.mp4 к предварительному измельчителю и проверить этот формат перед добавлением других роликов.

## Исходный ролик

Полный файл получен из [релиза GitHub v0.5.0](https://github.com/Eduyard13/Website_ERA/releases/tag/v0.5.0). Размер — 47 412 133 байта, SHA-256 — 1537bb5763b2ed8910b3306cf29311f55a9fb92404a758afa2645112638a3833. Контрольная сумма скачанного файла совпала с опубликованной GitHub. В public/assets/videos/predvaritelnyy-izmelchitel.mp4 сохранены те же байты.

ffprobe: длительность 104,52 секунды, 1920×1080, 25 кадров/с, H.264 High / yuv420p, стереозвук AAC-LC 48 кГц. Метаданные moov уже находятся перед mdat, поэтому перекодирование и перестановка контейнера не требуются. Полная проверка декодирования FFmpeg выполнена без ошибок. Содержание, длительность, качество и звук сохранены.

Постер извлечён из самого ролика на 10-й секунде: общий вид измельчителя в работе. Полная копия WebP имеет 1920×1080, миниатюра — 800×450. На постере сохранены подписи и маркировка исходного кадра. Источник, контрольные суммы, длительность, кодеки, размеры и время кадра сохранены в content/equipment-videos.mjs; запись имеет ready:true.

## Оформление и воспроизведение

Готовый видеоблок располагается после первого экрана и навигации по карточке, перед назначением. В первом экране и навигации появляется переход «Смотреть видео» / «Видео». У узлов без готовых роликов этих элементов нет. Несколько роликов одного узла поддерживаются общей записью медиатеки: первый показан крупно, остальные — дополнительными карточками.

Тёмный экран с постером открывает диалог с затемнением страницы, нативным видеоплеером, звуком, перемоткой, полноэкранным режимом и ссылкой на отдельный файл. MP4 не загружается при открытии страницы: src назначается только после действия пользователя. На мобильных используется playsinline. Закрытие, переход к другому материалу и Escape останавливают воспроизведение и освобождают источник. Фокус возвращается к открывшему элементу. Ошибка источника показывает доступную альтернативу и не блокирует закрытие.

Плеер общий для карточек узлов и вкладки «Видео» галереи. Изображения продолжают открываться в том же просмотрщике. Отдельные кадры из PDF остаются типом frame, а не видео.

Локальный сервер передаёт MP4 как video/mp4 и поддерживает потоковую выдачу, запросы диапазонов байтов (206), HEAD и ответ 416 на недоступный диапазон. Это позволяет проверять перемотку без чтения всего файла сервером в память. Для публикации на GitHub Pages сервер Node не требуется.

## Проверки

npm test проверяет необязательность блока, соответствие страницы узлу, путь GitHub Pages, постеры, безопасные подписи, отсутствие преждевременной загрузки в разметке, точный размер и SHA-256 полного MP4, а также порядок moov/mdat. test/video.browser.py создаёт синтетический восьмисекундный клип в отдельном временном каталоге и проверяет механизмы плеера, включая ошибку источника. Тестовый клип не попадает в public, Git или опубликованный сайт.

test/equipment-video.browser.py отдельно воспроизводит настоящий ролик на ширинах 360, 768 и 1440: проверяет точную длительность, разрешение и декодированные кадры, перемотку, полноэкранный режим, остановку и освобождение источника, возврат фокуса, фильтр видео и отсутствие загрузки MP4 до нажатия. В обоих сценариях используется Chromium; Safari и физические мобильные устройства в облачной среде не проверяются.

## Добавление следующих роликов

Проверить исходник через ffprobe и полное декодирование, просмотреть кадры. Использовать совместимый MP4 H.264/AAC с yuv420p и faststart; уже совместимый исходник сохранять без перекодирования. Сохранить оригинальное имя, размер, длительность и SHA-256 в реестре. Выбрать постер после просмотра самого ролика. Затем включить ready, обновить версию ресурсов, проверить реальный файл в браузере и публиковать новую версию сайта. Записи ready:false не создают видеоблоков, кнопок и пустых карточек в медиатеке.
