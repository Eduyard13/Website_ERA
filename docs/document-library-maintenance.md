# Пополнение инженерной библиотеки ЭРА

Библиотека `/documents/` и страницы пяти категорий используют один реестр `content/document-library.mjs`. Исходные 24 документа узлов остаются в `content/document-manifest.mjs`; два техописания линий приходят из их существующих описаний, обзор линии 02 — из `content/technology-lines.mjs`. Адреса оригиналов не меняются.

## Добавление опубликованного документа

1. Убедитесь, что содержание и публичный доступ согласованы. Разместите оригинальный PDF в `public/documents/brochures/`, `technical/`, `layouts/`, `drawings/` или `investments/`. Не изменяйте и не переименовывайте уже опубликованный файл: для новой редакции нужен новый стабильный id и отдельное имя.
2. Выполните `npm run documents:inspect -- <папка/имя.pdf>`. Команда выводит проверенные `pages`, `bytes`, `sha256`. Нужен Poppler (`pdfinfo`).
3. Добавьте одну запись в `additionalDocuments` в `content/document-library.mjs`: стабильный `id`, `title`, `category`, `type`, `objectType`, `objectSlug`, краткое подтверждённое `description`, `file`, `downloadName`, проверенные `pages`, `bytes`, `sha256`, `access:'public'`, `status:'published'`. Объекты берутся из `libraryObjects`; названия и обратный адрес подхватываются автоматически. Для проекта: `objectType:'project'`, `objectSlug:null`.
4. Запустите `npm run documents:covers`. Первая страница каждого нового PDF рендерится Poppler в пропорциях оригинала, до 840 px по длинной стороне; Pillow сохраняет WebP. Обложка и сведения о её происхождении попадают в `public/assets/document-covers/<id>.webp` и `content/document-covers.json`. Существующие обложки с правильным SHA не пересоздаются.
5. Выполните `npm run documents:validate`, `npm test`, `BASE_PATH=/Website_ERA npm test`, `BASE_PATH=/Website_ERA npm run build`. Библиотека, категория и подборка объекта обновятся автоматически, без изменения HTML/CSS. При необходимости выполните `ERA_PREVIEW_URL=http://127.0.0.1:3047/Website_ERA python3 test/documents.browser.py` — без скриншотов.
6. Закоммитьте PDF, запись, WebP и обновлённые метаданные. Публикация — штатный push в `main` и успешный workflow GitHub Pages.

Для локальной подготовки: Node.js >=22.13, `npm ci --omit=optional`; Poppler (`pdfinfo`, `pdftoppm`) и Python 3 с Pillow. В Ubuntu: `sudo apt-get install poppler-utils python3-pil`. В CI обложки не рендерятся: используются проверенные закоммиченные WebP. PDF.js 6.5.438 и fflate 0.8.3 поставляются локально из зафиксированных npm-зависимостей, worker, CMaps, шрифты, WASM и лицензии копируются сборкой. Внешних CDN нет.

## Реальный пример метаданных

Уже опубликованный обзор полной линии 02:

```js
{
  id: 'separatsiya-02-overview',
  title: 'Визитка линии сухой сепарации плёнок и пакетов',
  category: 'brochures',
  type: 'Брошюра линии',
  objectType: 'line',
  objectSlug: 'separatsiya-02',
  description: 'Сухая сепарация с сортировочной площадкой, пятью бункерами и автоматическим прессом.',
  file: 'brochures/era-separatsiya-02-overview.pdf',
  downloadName: 'ЭРА — Визитка линии сухой сепарации плёнок и пакетов.pdf',
  pages: 3,
  bytes: 4022808,
  sha256: '80876c22af16480aafa298b7a0630b26c2a88a9341d577867300a49e7b58a068',
  access: 'public',
  status: 'published'
}
```

Этот документ уже включён через `drySeparationOverview`; не добавляйте его повторно в `additionalDocuments`. Пример показывает поля реального материала, а не новый документ. Файл `technical/era-separatsiya-01-technical-description.pdf` относится к **полной линии 02**; мини-линия 01 использует файл с `mini` в имени. Принадлежность определяется реестром, не именем PDF.

## Категории, версии и ограниченный доступ

Допустимые категории: `brochures`, `technical`, `layouts`, `drawings`, `investments`. Схемы описывают технологию, чертежи — геометрию и монтаж. Не добавляйте неподтверждённые характеристики, даты, доходность или реквизиты. `revision` и `publishedAt` остаются `null`, пока редакция/дата не подтверждены источником.

Для подтверждённого материала по запросу запись имеет `access:'request-only'`, `status:'published'`, `file:null`, без обложки и скачивания. Сам PDF должен отсутствовать в `public/` и `dist/`. Показывается описание и кнопка существующей формы. Скрытая папка GitHub Pages не ограничивает доступ. `status:'preparing'` не создаёт фиктивную карточку; пустая категория уже имеет оформление и кнопку запроса.

Валидатор останавливает сборку при дубликатах, неизвестной категории/объекте, небезопасном пути, неверном PDF-заголовке, размере, SHA или происхождении обложки. О PDF без записи выводит предупреждение: добавьте подтверждённую запись либо уберите непубличный материал из `public/` перед публикацией.

## Ссылки, просмотр и ZIP

Старое `/documents?product=ballisticheskiy-separator` работает. Новые подборки: `/documents/?objectType=node&product=ballisticheskiy-separator` и `/documents/?objectType=line&product=separatsiya-02`. Допустимы `q`, `category`, `sort=name|category`; старый `kind` приводится к категории. Параметры сохраняются через `replaceState`; Back/Forward восстанавливает выбранное состояние при возвращении на страницу, без отдельной записи истории на каждый символ.

PDF.js и worker загружаются при открытии первого документа. Рендерится текущая страница, предыдущая задача отменяется, при закрытии ресурсы документа и worker освобождаются. Прямое открытие PDF и скачивание работают независимо от просмотрщика, в том числе без JavaScript.

ZIP формируется только в браузере после явного выбора, без пересжатия PDF. Лимит — 50 000 000 исходных байт. При превышении выделение сохраняется, показываются отдельные ссылки. Архив не создаётся на сервере. Изолированный тест новой схемы хранится только во временном каталоге и не включается в `public/` или публикацию.
