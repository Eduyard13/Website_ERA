# Однократное подключение SFTP и GitHub Actions

## 1. Сверьте основу на хостинге

В ispmanager откройте **Сайты / WWW-домены → era-cycle.ru** и запишите действительный абсолютный путь каталога сайта. Соседний с `www` закрытый каталог `era-deploy` создайте с правами `0700`. В `era-staging` разместите `regru_verify.php` и `archive-0.47.0.json` из подготовленного комплекта. Эти файлы описывают исходный архив 0.47.0. Проверьте файлы, которые реально установлены.

```text
ПУТЬ_К_PHP_8_3 -f /ФАКТИЧЕСКИЙ_ПУТЬ/era-staging/regru_verify.php -- /ФАКТИЧЕСКИЙ_ПУТЬ/www/era-cycle.ru /ФАКТИЧЕСКИЙ_ПУТЬ/era-staging/archive-0.47.0.json --record
```

Путь PHP CLI проверьте в панели или у поддержки. Ранее для этого тарифа рассматривался `/opt/php/8.3/bin/php`. При отсутствии терминала можно запустить эту команду один раз через планировщик и снять её после результата. Успех записывает `era-deploy/live-manifest.json` с правами `0600`. При расхождении покажите список `MISMATCH` и подтвердите фактическую версию до настройки. После ручного патча так же проверяется его `LIVE_AFTER.json`.

Скачайте только получившийся `live-manifest.json` из закрытой папки. Из проверенной рабочей ветки выполните команду ниже. Она записывает одну проверенную копию в отдельную ветку `regru/live-state`, где сохраняется история релизов.

```bash
bash scripts/regru_record_state.sh /путь/к/live-manifest.json
```

## 2. Подтвердите доступ на своём тарифе

В личном кабинете Рег.ру откройте услугу хостинга и её данные доступа. Сверьте у поддержки возможность SFTP по ключу, реальный адрес SSH, порт, пользователя и ограничения каталога. У аккаунта должны быть права на выбранный веб-корень и только служебный `era-deploy` вне сайта. Уточните поддержку атомарного переименования OpenSSH `posix-rename` между этими каталогами. Ключ для деплоя подготовьте отдельный, его публичную часть установите по инструкции хостинга. Строку `known_hosts` сверяйте с подтверждённым отпечатком SSH-хоста от провайдера. [Справка Рег.ру по SSH](https://help.reg.ru/support/hosting/dostupy-i-podklyucheniye-panel-upravleniya-ftp-ssh/rabota-po-ssh-na-virtualnom-hostinge)

## 3. Настройте окружение GitHub

В `Eduyard13/Website_ERA → Settings → Environments` создайте `reg-ru`. Ограничьте доступ к нему тегами `regru-deploy-*` и `regru-rollback-*`. Если доступен **Required reviewers**, укажите владельца. При одном reviewer настройте возможность подтверждения собственного запуска, если утверждает тот же владелец. Ограничьте изменение ветки релиза и создание тегов подтверждения доверенными участниками. Workflow принимает теги утверждения только от аккаунта владельца репозитория `Eduyard13`. [Документация GitHub по окружениям](https://docs.github.com/en/actions/how-tos/deploy/configure-and-manage-deployments/manage-environments)

В **Environment secrets** добавьте проверенные значения.

| Имя | Откуда брать |
|---|---|
| `SFTP_HOST`, `SFTP_PORT`, `SFTP_USER` | Подтверждённые настройки доступа конкретного аккаунта Рег.ру. |
| `SFTP_KEY` | Закрытая часть отдельного ключа доступа, установленного на хостинге. Для неинтерактивного запуска используйте поддерживаемый для CI ключ. |
| `SFTP_KNOWN_HOSTS` | Строка ключа хоста, сверенная с отпечатком Рег.ру. Для нестандартного порта соблюдайте синтаксис OpenSSH. |
| `REGRU_WEB_ROOT` | Проверенный абсолютный путь, оканчивающийся на `/www/era-cycle.ru`. Он должен соответствовать представлению файловой системы именно для SFTP. |

После проверки всех значений откройте **Settings → Secrets and variables → Actions → Variables** и создайте переменную репозитория `REGRU_SFTP_ENABLED=true`. До этого запуск передачи пропускается. Если Required reviewers недоступен, первым действием остаётся Prepare, вторым — отдельный тег владельца на конкретный проверенный SHA. [Правило GitHub для ручного запуска workflow](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow#defining-inputs-for-manually-triggered-workflows)

Теперь подготовьте новый патч от записанной базы и одобрите его с помощью `ERA_REGRU_UPDATES.md`. Ключ и пароль передаются только в указанные настройки. SMTP-пароль хранится в закрытом `era-private/config.json` на хостинге.
