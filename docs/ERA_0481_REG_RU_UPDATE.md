# ЭРА 0.48.1 · Установка на Рег.ру

Установку выполняет владелец сайта после проверки комплекта. Для этой версии нужны два подтверждения владельца. Первое разрешает обычный ZIP-патч, второе — замену двух юридических страниц и закрытого PHP-обработчика. Приём заявок остаётся выключенным.

## 1. Проверьте комплект и состояние 0.48.0

1. Скачайте оба ZIP и сопроводительные файлы. Распакуйте внешний архив GitHub Actions, если скачали комплект оттуда. В общей папке проверьте контрольные суммы и целостность ZIP.

   ```bash
   sha256sum -c SHA256SUMS
   unzip -t ERA_UPDATE_0.48.1.zip
   unzip -t ERA_PROTECTED_0.48.1.zip
   ```

   В Windows контрольную сумму отдельного файла выводит `Get-FileHash -Algorithm SHA256 .\ERA_UPDATE_0.48.1.zip` в PowerShell. Сравните её со строкой для этого файла в `SHA256SUMS`.

2. В ispmanager откройте настройки сайта `era-cycle.ru` и узнайте фактический корень сайта. В **Менеджере файлов** создайте закрытую папку `era-staging/0.48.1` рядом с `www`. Загрузите комплект в неё. Обычный ZIP распакуйте в `patch`, защищённый — в `protected`. Архивы, манифесты, инструкции и резервные копии храните в закрытой папке.
3. В терминале, доступном через панель или действующий доступ к хостингу, подставьте свои абсолютные пути. Повторите `sha256sum -c SHA256SUMS` в закрытой папке. Утилиты запускаются через PHP CLI 8.3. При отсутствии терминала эту проверку можно выполнить через поддержку хостинга.

   ```bash
   WEB='/фактический/путь/www/era-cycle.ru'
   PRIVATE='/фактический/путь/era-private'
   STAGING='/фактический/путь/era-staging/0.48.1'
   PHP='/фактический/путь/к/php8.3'
   cd "$STAGING"
   sha256sum -c SHA256SUMS
   "$PHP" "$STAGING/regru_verify.php" "$WEB" "$STAGING/patch/BEFORE.json"
   ```

   Ожидается `Verified 0.48.0 (ca9b8f6ee4a08e82dce65cafa8a80569bf3dd680), 1071 public files.` База взята из `LIVE_AFTER.json` патча 0.48.0. При `MISMATCH` остановитесь до выяснения расхождения.

4. В том же терминале проверьте закрытый режим заявок. Команда выводит только состояние переключателя. Отсутствующий конфиг также блокирует заявки. При неожиданном значении остановите установку и согласуйте состояние отдельно.

   ```bash
   "$PHP" -r 'if (!is_file($argv[1])) { echo "NO_CONFIG\n"; exit; } $c=json_decode(file_get_contents($argv[1]),true,16,JSON_THROW_ON_ERROR); if (($c["requests_enabled"]??null)!==false) { fwrite(STDERR,"STOP\n"); exit(1); } echo "REQUESTS_DISABLED\n";' "$PRIVATE/config.json"
   ```

## 2. Установите обычный патч после первого подтверждения

1. В `PATCH_MANIFEST.md` отметьте пути `UPDATE` и `ADD`. Сохраните **все** `UPDATE` из корня сайта в `era-staging/0.48.1/backup/public`, сохраняя структуру каталогов и права файлов. Убедитесь, что путей `ADD` на хостинге ещё нет. Если такой путь занят, остановитесь и сравните содержимое.
2. В Менеджере файлов перенесите из `patch/files/` только пути из списка. Сначала CSS, JavaScript и три PDF, затем HTML. При предложении заменить каталог целиком откройте его и скопируйте конкретные файлы с сохранением соседних страниц и медиа.
3. Проверьте обычный патч. Манифест действующей версии охватывает управляемые публичные файлы и исключает защищённые пути.

   ```bash
   "$PHP" "$STAGING/regru_verify.php" "$WEB" "$STAGING/LIVE_AFTER.json"
   ```

   Ожидается версия `0.48.1` и `1076 public files`.

## 3. Установите защищённый комплект после отдельного подтверждения

1. Проверьте `MANIFEST.json` из защищённого комплекта. Его `commit` должен совпасть с `commit` в `LIVE_AFTER.json`. Проверьте файлы в закрытой папке до копирования.

   ```bash
   "$PHP" "$STAGING/regru_verify_0481_protected.php" "$STAGING/protected/MANIFEST.json" \
     "$STAGING/protected/public" "$STAGING/protected/private"
   ```

2. Сохраните действующие файлы по путям из таблицы в `era-staging/0.48.1/backup/protected`. Отдельно запишите, каких файлов до установки не было. Сохраните исходные SHA-256, права и владельцев существующих файлов. Проверьте, что резервные копии читаются и имеют те же SHA-256. Пути в рабочем сайте могут содержать редакции, которые владелец устанавливал отдельно.

   | Источник в защищённом комплекте | Путь на сервере |
   | --- | --- |
   | `public/privacy/index.html` | `$WEB/privacy/index.html` |
   | `public/privacy/consent/index.html` | `$WEB/privacy/consent/index.html` |
   | `private/request-handler.php` | `$PRIVATE/request-handler.php` |

3. Подтвердите установку именно этих трёх файлов и соответствующего коммита. В Менеджере файлов скопируйте сначала две страницы, затем `request-handler.php` в действующий закрытый каталог рядом с `www`. Сохраняйте существующие права. Используйте уже установленный `config.json`. SMTP, SSH, журналы, данные валют и `api/request.php` исключены из комплекта.
4. Проверьте все три файла на месте. Команда читает только указанные файлы и манифест.

   ```bash
   "$PHP" "$STAGING/regru_verify_0481_protected.php" "$STAGING/protected/MANIFEST.json" "$WEB" "$PRIVATE"
   ```

## 4. Проверьте сайт после двух этапов

- Откройте `/privacy/`, `/privacy/consent/` и `/privacy/cookies/` в приватном окне. Сверьте редакции `ERA-PRIVACY-1.3`, `ERA-PD-1.3` и `ERA-COOKIES-1.3` и скачайте PDF. Для всех трёх URL в `/privacy/files/` ожидается `Content-Type: application/pdf`. Сравните SHA-256 со списком файлов.
- На главной откройте настройки с клавиатуры, закройте по Escape, затем отклоните карты. Перейдите в контакты, откройте настройки из футера, разрешите и снова отклоните карты. В сборке 0.48.1 открытие по внешним ссылкам доступно. Встроенные карты появятся после отдельного решения оператора.
- Проверьте отдельную пустую галочку в контактной форме и в модальном окне. Для `GET /api/request.php` ожидается `405`. Приём заявок остаётся выключенным. На этом этапе проверка SMTP и регистрация факта согласия выполнены в изолированном окружении. Для отдельного включения на хостинге владелец проверяет локализацию баз и почты в РФ, уведомление Роскомнадзора, доступы, настройку SMTP, хранение и удаление данных по указанному сроку и условия подключения сторонних сервисов.
- Проверьте каталог, четыре линии, схемы, экономику, видео с перемоткой и техническую библиотеку. Повторите обе проверки манифестов. Если уже ведёте `regru/live-state`, запишите проверенный `LIVE_AFTER.json` штатным порядком после проверки обоих комплектов. Защита двух страниц сохраняется для следующих обычных патчей.

## 5. Откат на 0.48.0

1. Оставьте приём заявок выключенным. Если меняли защищённые файлы, восстановите их из `backup/protected` по записанным исходным путям, SHA-256 и правам. Файл, которого до установки не было, переместите из публичного или закрытого рабочего каталога в папку отката после сверки его SHA-256 с `MANIFEST.json`.
2. Верните `UPDATE` из `backup/public`, сохраняя права и структуру. Новые пути `ADD` после сверки с `RELEASE.json` переместите в закрытую папку отката. Другие файлы, конфиг и валютный JSON остаются под существующей защитой.
3. Запустите `regru_verify.php` с `patch/BEFORE.json`, повторно сверьте исходные SHA-256 защищённых файлов и отсутствие изначально отсутствовавших путей. Ожидается `Verified 0.48.0 … 1071 public files.` Если манифест уже записывали на сервере и в `regru/live-state`, запишите обратно подтверждённый `BEFORE.json` штатным порядком.
