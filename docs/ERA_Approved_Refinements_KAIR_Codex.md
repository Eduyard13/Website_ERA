# ЭРА — согласованные правки текстов, подвала и блока КАИР

Задание для Codex. Дата: 1 ноября 2026 года.

При подготовке точечно просмотрена опубликованная версия **0.11.2**. Этот документ задаёт следующий пакет изменений, одобренный владельцем проекта.

## 1. Результат и границы пакета

Выполни шесть изменений:

1. Отредактируй служебный язык по всему сайту: убери из клиентских текстов рассуждения о презентациях, предоставленных КП, исходниках и внутренних согласованиях.
2. Приведи название бренда в текстах к единому кириллическому написанию **«ЭРА»**.
3. Перенеси валютный блок из шапки в подвал; сгруппируй ссылки подвала по той же структуре, что и большое меню.
4. Визуально раздели нижний блок обращения на главной и подвал, устранив повторный старт градиента на их стыке.
5. Замени неоднозначные счётчики вида «11 материалов» на явные типы содержимого: фото, видео, схемы/визуализации, документы.
6. Преврати изображение КАИР на главной в презентационный монитор: тонкая рамка, аккуратная стойка, качественная подача экрана. Подготовь компонент к будущим слайдам; сейчас показывай существующий скриншот без автоматической смены.

Сохрани действующие страницы, данные, маршруты, характеристики оборудования и навигацию **О проекте → Оборудование → Технология → Все разделы**. Этот пакет не включает другие рекомендации прежнего аудита автоматически: он не требует перестройки каталога, подключения веб-формы, публикации новых комплектаций или функций ИИ.

Согласованная палитра из `ERA_Cosmic_Indigo_Codex.md` сохраняется: основной индиго `#10132E`, свечение `#353960`, глубокая тень `#050714`, золото `#C6A43B`, тёплый белый `#F7F4EE`. **Новое уточнение: нижний блок обращения на главной становится светлым; подвал остаётся индиговым.**

## 2. Редактура: говорить с клиентом о решении

### Что убрать

Пройди все шаблоны и данные, а не только главную. Найди такие обороты и их смысловые варианты:

- «из презентации», «в презентации описано», «что раскрывает презентация»;
- «по предоставленному КП», «по представленному КП», «из предоставленных материалов»;
- «исходный материал», «исходник», «слайд №…» — когда речь о происхождении текста или картинки;
- «материалы пока не предоставлены», «требует подтверждения» и другие внутренние редакционные статусы;
- «сайт объединяет…», «структура страницы подготовлена…» и объяснения того, как разрабатывается сайт;
- дублирующиеся осторожные абзацы, которые описывают процесс подготовки публикации вместо оборудования.

Проверь заголовки, абзацы, карточки, подписи изображений, просмотрщики, всплывающие подсказки, названия фильтров, alt, aria-label, title, description, Open Graph и темы писем. В клиентском режиме служебные обозначения «Прототип», «для согласования» и номер сборки также не должны занимать место в интерфейсе. Если в проекте нужен отдельный режим предпросмотра, оставь эти отметки только в нём. Сам запрет индексирования этим редакционным пакетом автоматически не отключай.

### Принцип новой редакции

Называй оборудование, процесс, функцию, результат и следующее действие клиента. Пиши коротко и предметно. Сведения об источниках при необходимости сохраняй в редакционных данных проекта; клиентский интерфейс не должен пересказывать историю загрузки файлов.

| Было | Как оформить |
| --- | --- |
| «Фото из презентации проекта» | Предметная подпись к изображению, например «Оборудование комплекса ЭРА» |
| «Полигонные пакеты и плёнки · фото из презентации» | «Полигонные пакеты и плёнки» |
| «Фотоотчёт изготовления оборудования · презентация ERA, слайд 24» | «Изготовление оборудования» |
| «Компоновка линии … из презентации ERA · слайд 11» | «Компоновка линии …». Тип материала «Визуализация» сохранить |
| «Контакты из предоставленного КП» | Удалить эту фразу; контакты показать непосредственно |
| «Параметры приведены по предоставленному КП» | Заголовок «Технические характеристики» и только полезные условия измерения/применения |
| «Изображение интерфейса, представленное в исходном материале» | «Интерфейс системы КАИР» |
| «Что раскрывает презентация» | «Возможности системы» — для функций, которые действительно описаны и подтверждены |
| «Состав функций и интеграции согласуется для конкретной комплектации» | «Состав системы подбирается под оборудование линии» |
| «Иллюстрации не представлены как единая серия испытаний» | Убрать редакционное объяснение. Подписать каждый образец по его назначению; не представлять разные материалы как один испытанный цикл |

Примеры адаптируй к фактическому изображению и содержимому. Не называй визуализацию фотографией, а чужую площадку — собственным производством.

### Технический смысл сохраняется

Удаляем внутреннюю редакционную неуверенность. Фактические условия работы оборудования формулируем уверенно и понятно:

- сохранить единицы измерения, диапазоны, условия подачи, подготовку сырья, варианты исполнения и ограничения совместимости;
- целевые показатели не превращать в безусловно гарантированные;
- расчётную потребляемую мощность не называть измеренным рабочим потреблением;
- «по согласованию» заменять предметным описанием выбора, когда это возможно, например «Ротор подбирается под плёнку или жёсткий пластик»;
- если для утверждения нет данных, убрать неподтверждённое обещание и оставить нейтральное описание задачи/направления с существующим способом обращения.

Для незаполненных участков не придумывай показатели и функции ради уверенного тона. Вместо внутреннего статуса можно оставить понятное действие по существующему направлению: «Обсудить комплектацию», «Подобрать решение под сырьё». Не оставляй страницу с обрывками текста после массового удаления фраз.

Названия самих типов документов — «Коммерческое предложение», «Паспорт», «Техническое описание» — сохраняются, если они верно описывают файл. Загруженные PDF в этом пакете не перевёрстываются.

### Готовые тексты для главной

Вместо описания «Сайт объединяет отдельные узлы…»:

> ЭРА объединяет оборудование, технологические линии и управление процессом переработки. Начинаем с вашего сырья и нужного результата, подбираем последовательность операций и состав оборудования.

Для блока КАИР:

> КАИР — система управления технологическим комплексом ЭРА. Состояние узлов, режимы работы и движение материала — в едином интерфейсе.

Короткие акценты: **Состояние оборудования / Режимы работы / Движение материала**.

Существующий заголовок **«Оборудование связано. Процесс под контролем.»** можно сохранить. Подпись к экрану: **«Интерфейс системы КАИР»**. Кнопка: **«Подробнее о КАИР»**, ведущая на существующую страницу управления.

## 3. Название бренда — только «ЭРА» в клиентском тексте

Правильная строка: **ЭРА**. Три кириллические буквы: `Э` — U+042D, `Р` — U+0420, `А` — U+0410. Используй написание как в действующем логотипе.

Заменить латинские `ERA`, `Era`, `era` и смешанные варианты букв, когда они являются отображаемым названием бренда:

- тексты страниц, меню, подвал, подписи, карточки, кнопки;
- title/description, Open Graph, подписи для доступности;
- название организации в структурированных данных, если оно присутствует;
- текст темы и тела почтового запроса после правильного URL-кодирования;
- авторские текстовые надписи в редактируемых интерфейсных SVG.

Примеры: «Каталог ЭРА», «Технология ЭРА», «Оборудование ЭРА», «Запрос ЭРА: Роторная центрифуга», «© 2026 ЭРА».

**Технические идентификаторы сохраняются.** Репозиторий `Website_ERA`, URL, пути к ресурсам, имена файлов, CSS-классы, переменные, ключи данных и адреса почты не переименовывать ради текстовой замены. Не применять глобальный replace ко всем байтам проекта.

Логотип используй существующий, с его исходной геометрией. Если текст находится внутри растрового изображения или PDF, это отдельный ресурс: не ломай файл и не перекрывай важные элементы изображения новым текстом. В отчёте перечисли такие вхождения, если они действительно обнаружены и требуют редактируемого оригинала.

## 4. Валюты — в подвал; ссылки — по группам большого меню

### Убрать валютную строку из шапки

Перенеси существующий компонент курсов в общий подвал всех страниц. Сохрани источник данных, обновление, дату актуальности и обработку недоступности сервиса. Не вставляй в код текущие числовые значения как постоянные.

После переноса:

- в шапке нет USD/EUR/CNY, кнопки ЦБ РФ и пустого места от старой валютной строки;
- навигация, логотип и кнопка обращения аккуратно выровнены в одной строке на настольном экране;
- мобильная шапка становится компактнее;
- высота закреплённой шапки и отступы якорей пересчитаны, чтобы заголовки не скрывались под ней;
- нет двух экземпляров компонента, повторных сетевых запросов или дублирующихся обработчиков.

### Состав подвала

Верхняя часть: действующий логотип, слоган **«Полный цикл переработки плёнки: очистить, переработать, использовать снова.»**, основные контакты.

Навигационная часть повторяет группы большого меню:

| Группа | Ссылки |
| --- | --- |
| Проект и технология | О проекте; Технология переработки |
| Оборудование | Общий каталог; Линии и комплексы; Отдельные узлы |
| Управление и цифровые решения | Система управления КАИР; Искусственный интеллект |
| Материалы | Фото и видео; Документация; Новости; Блог |
| Связь и сведения о предприятии | Контакты; Реквизиты |

Используй общую модель навигации для большого меню и подвала, если это позволяет текущая архитектура. Так названия, адреса и уже существующие настройки видимости будут совпадать. Этот пакет сам по себе не вводит новое решение о скрытии разделов.

Нижняя дополнительная строка: **Курсы ЦБ РФ / USD / EUR / CNY**, дата, раскрытие сведений об источнике; затем компактная строка копирайта. Ссылку на источник и дату сохранить: они помогают понять актуальность курсов и не относятся к удаляемым редакционным пояснениям.

На широком экране группы располагаются в пять колонок, когда им хватает места; на среднем — переносятся в две/три колонки. На телефоне — одна колонка; группы можно оформить доступными сворачиваемыми секциями. Телефон и почта остаются видимыми без раскрытия навигационных групп. Валюты переносятся по строкам без горизонтальной прокрутки. Раскрытие источника не должно выходить за нижнюю границу страницы: подойдут сведения в потоке документа.

Не превращай подвал в плотную строку из всех ссылок. У групп — ясные названия, у ссылок — комфортный интервал и видимый клавиатурный фокус.

## 5. Нижний блок обращения и подвал: разные поверхности

### Причина текущего стыка

В версии 0.11.2 у `section#discuss.discuss-story` и у `footer` есть класс `era-indigo-surface`. Каждый элемент самостоятельно начинает один и тот же градиент. Поэтому соседние тёмные секции сливаются по назначению, но световые пятна скачком меняются на их границе.

### Принятое решение

**Блок обращения — светлый. Подвал — индиговый.**

| Элемент | Оформление |
| --- | --- |
| Фон блока обращения `#discuss` | Тёплый белый `#F7F4EE`, без градиента, точек и зерна |
| Заголовок, телефон, ссылки | Индиго `#10132E` |
| Вторичный текст | Существующая контрастная роль для светлого фона |
| Небольшой золотистый акцент | Контрастный тёмный золотой из действующей темы; не светлое золото мелким текстом на белом |
| Основная кнопка обращения | Индиго, светлый текст; наведение — утверждённое свечение индиго |
| Фон подвала | Один общий градиент «Космический индиго» на корневом контейнере подвала |
| Текст подвала | Тёплый белый; золото для умеренных акцентов |

У светлого блока обращения убери `era-indigo-surface` и его декоративные слои; обнови цвета дочерних надписей, кнопок, ссылок, рамок и состояний. Перекрасить только фон недостаточно: белые надписи не должны остаться на светлой поверхности.

Сохрани содержание, телефон, почту, якорь `#discuss` и существующую механику обращения. Сейчас это блок с почтовым действием; новая веб-форма этим заданием не добавляется.

Подвал получает фон только на одном общем контейнере. Логотип, группы ссылок, контакты и валютная строка находятся на прозрачных внутренних поверхностях; они не запускают собственные радиальные и диагональные градиенты. Сохрани одну пару световых полей и один декоративный слой фактуры на весь подвал согласно заданию индиго.

Не пытайся подгонять два независимых градиента отрицательными отступами, огромным `background-size`, `background-attachment: fixed` или случайными смещениями. Светлый блок и тёмный подвал должны иметь чистую видимую границу при любой высоте текста и ширине окна.

Ориентир вертикальных отступов блока обращения: 64–80 px на настольном экране и 40–48 px на телефоне; адаптируй к существующей сетке. Внутри — заголовок с пояснением и самостоятельная зона действия. Подвал начинается отдельным блоком без промежуточной пустой тёмной полосы.

## 6. Счётчики: отдельно фото, видео, схемы и документы

Замени «11 материалов», «7 материалов», «4 материала» и аналогичные суммарные подписи там, где они обозначают содержимое карточки оборудования. Не затрагивай слово «материал», когда речь идёт о перерабатываемом сырье.

Формат подписи:

```text
Фото: {photos} · Видео: {videos} · Схемы: {schemes} · Документы: {documents}
```

Правила:

- Значения вычисляются из реально доступных ресурсов соответствующего узла.
- Группы с нулевым количеством не показываются.
- «Открыть» и «Скачать» одного PDF — один документ.
- Миниатюра, полноразмерный файл и адаптивные разрешения одного фото — одна фотография.
- Одно видео, показанное в карточке и общей галерее, не считается дважды в счётчике узла.
- Схемы и визуализации классифицируй по существующей модели. Если они объединены в одну группу, подпиши её **«Схемы и визуализации»**, а не называй 3D-рендер фотографией.
- Документы могут иметь уточнение формата PDF, если все посчитанные файлы действительно PDF.
- Подписи переносятся на две строки на узком экране без обрезки и горизонтальной прокрутки.

Если отдельные категории пока нельзя надёжно посчитать, используй явные текстовые типы без числа, например «Фото, схемы и документы», вместо выдуманного счётчика. Предпочтительный итог — точные количества из данных проекта.

Сохрани или добавь переход к соответствующему разделу карточки/медиатеки там, где это помогает просмотру. Не добавляй кликабельное оформление без действительного перехода.

## 7. КАИР — презентационный монитор

### Образ

Экран должен восприниматься как дорогой профессиональный монитор на выставочном стенде: крупный, спокойный, с тонким корпусом и аккуратной опорой. Главный акцент — настоящий интерфейс системы. Рамка поддерживает изображение и не спорит с ним.

Сохрани индиговую секцию КАИР как самостоятельный демонстрационный блок. На широком экране текст занимает примерно 35–40% ширины, монитор — остальное. Если для читаемого экрана двух колонок недостаточно, на среднем размере перенеси монитор ниже текста. На телефоне — одна колонка.

### Корпус и опора

| Часть | Требование |
| --- | --- |
| Положение | Почти фронтально; без сильной перспективы и наклона, искажающих надписи интерфейса |
| Корпус | Тёмный графит/глубокий индиго; тонкая нейтральная металлическая грань |
| Рамка | Ориентир 8–12 px на настольном экране, 5–7 px на телефоне; пропорционально размеру компонента |
| Углы корпуса | Умеренные, ориентир 12–16 px; экран не должен выглядеть смартфоном с чрезмерным скруглением |
| Стойка | Небольшая центральная опора и низкое аккуратное основание, без массивного пьедестала |
| Тень | Мягкая опорная тень под корпусом/основанием; без тяжёлого чёрного ореола |
| Отражения | Только очень слабый отблеск на грани корпуса; важные надписи и данные на экране остаются чистыми |
| Золото | Небольшая подпись КАИР или один тонкий акцент; не золотой корпус и не яркое свечение по периметру |

Рамку, стойку и тени сделай средствами HTML/CSS или существующих компонентов. Скриншот должен остаться самостоятельным изображением; не запекай весь монитор вместе с текстом секции в одну картинку.

Не добавляй чужие марки мониторов, браузерную/операционную шапку, декоративные кнопки без действия, RGB-подсветку и заметные блики поверх интерфейса.

### Сам экран

- Область экрана имеет стабильное соотношение сторон, рабочий ориентир **16:9**.
- Скриншоты показываются целиком: `object-fit: contain`, центрирование, без обрезки верхних панелей, чисел и подписей.
- При разных пропорциях использовать спокойные тёмные поля; высота монитора не должна прыгать при смене изображения.
- Пропорции, цвета, цифры и элементы настоящего интерфейса сохраняются. Цветовое оформление сайта не перекрашивает данные скриншота.
- Не имитировать на сайте работающую телеметрию, живые показатели или управление настоящим оборудованием. Это демонстрация экранов системы.
- Предусмотреть открытие исходного изображения крупно через существующий доступный просмотрщик или понятное действие «Рассмотреть интерфейс».

Для корректной геометрии можно использовать такой базовый принцип, адаптировав имена классов к проекту:

```css
.kair-monitor-screen {
  position: relative;
  aspect-ratio: 16 / 9;
  background: var(--era-deep);
  overflow: hidden;
}

.kair-monitor-screen img {
  display: block;
  width: 100%;
  height: 100%;
  object-fit: contain;
  object-position: center;
}
```

### Материал на текущем этапе

Сейчас подтверждён существующий ресурс `assets/presentation/kair.webp`, размер **616 × 361 px**. Он используется на главной версии 0.11.2.

Используй его как единственный текущий экран, пока не добавлены новые материалы. Не создавай несколько одинаковых слайдов и вымышленные панели. Рамка и вёрстка могут быть чёткими уже сейчас; детализация исходного скриншота ограничена его реальным разрешением.

Для следующего обновления желательны оригинальные скриншоты примерно 1920 × 1080 или крупнее, с подходящими пропорциями; ориентир — до двух физических пикселей исходника на CSS-пиксель показанного изображения. Это цель для новых исходников, а не обещание повысить детализацию имеющегося файла.

## 8. Подготовка к будущей смене слайдов

### Сейчас

Сделай повторно используемый компонент монитора с массивом экранов и настройками показа. В массиве сейчас один реальный скриншот. Автоматическое перелистывание **выключено**. При одном элементе нет стрелок, точек, таймера, счётчика «1 из 1» и кнопки паузы.

Пример структуры данных, а не требование сменить стек:

```js
const kairSlides = [
  {
    id: 'overview',
    assetPath: 'assets/presentation/kair.webp',
    width: 616,
    height: 361,
    alt: 'Интерфейс системы КАИР: управление технологическим комплексом ЭРА',
    caption: 'Интерфейс системы КАИР'
  }
];

const kairPresentation = {
  autoplay: false,
  intervalMs: 7000,
  transitionMs: 800
};
```

`assetPath` разрешай через существующую систему базового пути проекта. Текущая публикация находится в `/Website_ERA/`; относительные ресурсы не должны ломаться на вложенных страницах. Не переименовывай существующие файлы ради написания бренда кириллицей.

Не добавляй тяжёлый слайдер ради одного изображения. Используй существующий подход проекта или небольшой компонент, который можно расширить после загрузки новых скриншотов.

### Следующий этап после получения изображений

Когда в массив добавят несколько реальных экранов, компонент должен поддерживать такую подачу:

- Спокойное плавное растворение одного экрана в другой, ориентир **800 мс**.
- Интервал показа — ориентир **7 секунд**; итоговую скорость уточним на реальных изображениях.
- Без перелистывания всей секции, вращения, зума надписей, движения корпуса монитора и скачков высоты.
- До переключения следующий файл загружен и готов к отображению; при ошибке изображения текущий экран остаётся видимым.
- Управление «Предыдущий», «Следующий», индикатор текущего кадра и «Пауза/Продолжить» расположены сдержанно рядом с подписью, за пределами скриншота.
- Все действия доступны с клавиатуры и имеют понятные русские подписи. Скрытые кадры не попадают в порядок фокуса.
- Автопоказ приостанавливается при взаимодействии пользователя, уходе вкладки в фон и выходе блока из области просмотра; явная пользовательская пауза не сбрасывается автоматически.
- При `prefers-reduced-motion` автосмена по умолчанию выключена, ручное переключение без длительной анимации доступно.
- Автоматическая смена не должна постоянно озвучиваться скринридером; ручной выбор можно сообщать коротко.

Подготовь эти возможности в структуре компонента и конфигурации, но **не включай автопоказ сейчас**. Следующее обновление должно сводиться к добавлению файлов и записей в массив, а затем включению нужного режима.
