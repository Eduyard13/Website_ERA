## 0. Задача, которую надо решить

Текущая библиотека функционально хороша, но при нажатии на категорию, например «Брошюры и презентации», пользователь попадает на `/documents/brochures/`, остаётся наверху и видит заново почти всю главную страницу библиотеки: крупный hero, повторение пяти больших категорий, а нужные PDF располагаются далеко ниже. Непонятно, что выбор уже произошёл.

Кроме того, на карточках PDF светлая титульная страница окружена слабоконтрастным фоном, почти совпадающим с фоном сайта. Не хватает визуального отличия карточки от основной страницы. На вложенных страницах документации, отдельных узлов и линий нужен понятный, доступный во время прокрутки возврат к родительскому разделу или предыдущей странице внутри сайта.

**Утверждённое решение:**

1. `/documents/` — **главная витрина библиотеки** с красивым большим первым экраном и пятью категориями, как сейчас. Не ухудшать её.
2. `/documents/brochures/`, `/documents/technical/`, `/documents/layouts/`, `/documents/drawings/`, `/documents/investments/` — **самостоятельные компактные внутренние страницы**. Не повторять крупную витрину категорий: после небольшой шапки сразу идёт навигация по пяти категориям, затем поиск и документы/честное пустое состояние.
3. Добавить единый **премиальный sticky-блок возврата** под шапкой сайта на внутренних страницах библиотеки и на страницах отдельных узлов/линий; реализовать «Назад» с правильным fallback, кликабельные breadcrumbs и отсутствие перекрытий.
4. Для PDF-карточек использовать **ТОЛЬКО утверждённый вариант №3 `Technical Archive`**: холодный стально-серый фон, тонкая инженерная графика / горизонтальные линии над и под документом, видимая контрастность карточки относительно сайта, аккуратная тень настоящей обложки. Не делать тёмный индиго-пьедестал (вариант №1) и не делать тёплую бежевую бумагу (вариант №2).
5. Сохранить всю существующую библиотечную функциональность: реальные PDF, обложки из первой страницы, фильтры, поисковый индекс, PDF-просмотрщик, выбор нескольких документов, ZIP, ссылки на оборудование/линии, адаптивность.

**Сфера работ ограничена UX-структурой, навигацией и оформлением этих страниц. Не трогать содержимое PDF, технологические тексты, цены, другие страницы, главную шапку, фирменную палитру и разделы проекта вне затронутой навигации.**

## 2. Информационная архитектура: главная библиотека отдельно от категорий

### 2.1. `/documents/` — главная витрина, крупный hero сохраняем

**Не превращать главную в сухой список**. На ней оставляем:

- большой тёмно-синий первый экран «Инженерная библиотека ЭРА»;
- описание смысла документов;
- пять визуальных карточек категорий;
- поиск по всем документам;
- общую выдачу;
- подборки по узлам и линиям;
- блок запроса документации;
- встроенный PDF-просмотрщик.

По клику на большую категорию — **настоящая навигация на отдельный URL**, без простого скрытия списка внизу главной и без JS-only якорной прокрутки.

### 2.2. Каждая категория — отдельная короткая страница

URL и названия строго сохранить:

| URL | H1 |
|---|---|
| `/documents/brochures/` | Брошюры и презентации |
| `/documents/technical/` | Технические описания |
| `/documents/layouts/` | Технологические схемы и компоновки |
| `/documents/drawings/` | Чертежи и габариты |
| `/documents/investments/` | Инвестиционные предложения |

Композиция страницы категории, **в указанном порядке**:

**A.** Sticky-панель возврата (`Назад` / `Документация / …`), сразу под глобальной шапкой, компактная.<br>
**B.** **Компактный intro** (вместо нынешнего огромного `.dl-hero`) — название выбранной категории, одна ёмкая строка-описание, реальное число PDF по категории. При желании — фирменная тёмно-синяя подложка высотой примерно 140–220 px на desktop и ещё компактнее на мобильном; без второй колонны декоративных текстов, без большого общего счётчика узлов/линий.<br>
**C.** **Тонкая полоска навигации по категориям** из пяти названий + «Все документы»; активная категория явно выделяется золотой линией / подложкой / `aria-current="page"`. По клику пользователь переходит на другой соответствующий URL.<br>
**D.** **Фильтры/поиск конкретной категории**, сразу после вкладок. Никакого второго крупного блока «Найдите нужный уровень детализации», никакой сетки из пяти огромных карточек.<br>
**E.** Заголовок «Документы категории» / название категории, реальный счётчик и выдача `.dl-document-grid` с текущими публичными PDF только этой категории; либо корректное пустое состояние с возможностью запросить материалы.<br>
**F.** При необходимости ниже — более компактная «Подборка по оборудованию» или запрос дополнительных материалов, но основной список документов должен показываться **первым**, а не после ещё одного большого набора блоков.

На desktop пользователь после перехода должен **без заметной дополнительной прокрутки увидеть как минимум начало раздела с PDF и желательно первый ряд обложек** при распространённых высотах окна. На мобильном — компактная шапка, категории в горизонтальной полосе, поиск и первые карточки без огромных промежуточных декоративных отступов. Не фиксировать только через `scrollIntoView` после загрузки: нужно устранить причину — лишнюю композицию.

### 2.3. Чёткие отличия внутренней страницы от главной

- Главная `/documents/` показывает **большие карточки пяти категорий**.
- Внутренние `/documents/<id>/` показывают **одну компактную шапку + горизонтальные табы**, без повторения большой сетки категорий.
- Во внутренней странице выбранный тип документов очевиден по H1, активной вкладке и документам, которые видны сразу.
- Счётчик «Документов: N» вычисляется динамически для выбранной категории и фильтров.
- Не делать faux-tabs, которые выглядят интерактивно, но не меняют URL.
- `noscript`: ссылки на категории и исходные PDF остаются работоспособны без JavaScript.

## 3. Короткая полоска категорий: поведение и внешний вид

### Desktop

Лёгкая навигационная полоса после intro в один ряд, если позволяет ширина; допустима аккуратная прокрутка по горизонтали. Пункты:

- `Все документы`
- `Брошюры и презентации`
- `Технические описания`
- `Схемы и компоновки` (допустимое короткое **визуальное** название, H1 остаётся полным)
- `Чертежи и габариты`
- `Инвестиционные предложения`

Линейная композиция: тёплый светлый/нейтральный фон страницы; тонкая горизонтальная граница; активная вкладка подчёркнута золотым акцентом ЭРА и слегка более плотной типографикой. Никаких крупных цветных кнопок и разноцветных иконок.

### Mobile

Горизонтальная лента с нативной прокруткой пальцем (`overflow-x:auto`, `scroll-snap` при уместности), без переноса названий в пять высоких строк. Активный пункт должен быть видимым при входе на страницу; не перекрывать контент. Скрытый scrollbar допустим только при понятной индикации продолжения. `focus-visible` обязательно.

### URL и параметры

- Категория — отражается в **пути URL** и доступна по прямой ссылке.
- Поиск, сортировка, тип объекта и конкретный объект — `URLSearchParams`, как сейчас.
- Когда пользователь из `/documents/?q=...` переходит в категорию — сохранить совместимые фильтры, если это действительно даёт корректную выдачу; но не допускать, чтобы невидимый старый фильтр вызывал пустой экран при новом выборе категории. Если нужно, очищать несовместимые параметры, сообщать о фильтрах в UI и давать «Сбросить».
- Не создавать двойных путей `/documents/brochures/brochures/`: код `document-library.js` уже вычисляет `home` из ссылки `[data-library-home]` — сохранить правильную точку отсчёта.
- Проверить прямые ссылки на все категории с GitHub Pages `BASE_PATH=/Website_ERA`.

## 4. Sticky-навигация «Назад» — общая для вложенных страниц

### 4.1. Область применения

Добавить компонент на:

- страницы категорий документов `/documents/<category>/`;
- отдельные страницы узлов `/catalog/equipment/<slug>/`;
- отдельные страницы линий `/catalog/lines/<slug>/`;
- при необходимости страницы подборок/конкретных объектов, если они действительно существуют как отдельные маршруты.

**Не добавлять новый sticky-компонент на главную `/` или на все страницы сайта без разбора.** Не делать вторую копию на той же странице. `/documents/` как корневая библиотека может иметь обычную незакреплённую навигационную цепочку или остаться без неё.

### 4.2. Визуал

Компактная горизонтальная премиальная полоса в стиле ЭРА:

- положение `position:sticky` **ниже существующей sticky-шапки**, с учётом её реальной высоты и мобильного брейкпойнта (`--site-header-space` или измерение шапки);
- полупрозрачный светлый фон с лёгким `backdrop-filter`, тонкий нижний border, золотой маркер текущего пути;
- слева кнопка `← Назад` (не просто иконка без подписи);
- справа/рядом — кликабельные breadcrumbs;
- никакого яркого баннера, больших скруглённых плашек или навязчивой анимации;
- desktop высота примерно 44–56 px, мобильная 42–50 px; минимальная интерактивная зона 44×44 px;
- учитывать `z-index`: ниже глобальной шапки и поверх обычного текста, но **ниже открытого меню, PDF-dialog, галереи и модальных форм**;
- при появлении компонента не допускать layout-shift, скачков якорей и наложения заголовков.

**Примеры текстов:**

- Внутренняя документация: `← Назад` | `Документация / Брошюры и презентации`.
- Узел: `← Назад` | `Каталог / Отдельные узлы / Баллистический сепаратор`.
- Линия: `← Назад` | `Каталог / Линии и комплексы / Сепарация 02`.

Все breadcrumbs — обычные настоящие ссылки на соответствующие родительские пути. Последний пункт — текущий текст, `aria-current="page"` уместен для последней ссылки, если она оставлена ссылкой.

### 4.3. Семантика возврата (критически важно)

**Нельзя использовать безусловный `history.back()`** — пользователь, пришедший из почты, Google или мессенджера, не должен попасть обратно за пределы ЭРА.

Алгоритм:

1. Кнопка содержит реальный `href` к **логичному родителю**, который работает без JS:
   - категория документов → `/documents/`;
   - узел → `/catalog/equipment/`;
   - линия → `/catalog/lines/`.
2. При наличии подтверждённой предыдущей записи в истории **этого же сайта**, переход можно сделать назад (`history.back()`), сохранив предыдущие фильтры/позицию прокрутки. Происхождение должно быть реально известно из контролируемой навигации: `sessionStorage` или `history.state` при переходе по ссылкам внутри сайта; `document.referrer` можно использовать как подсказку, но он не доказывает существование безопасной предыдущей записи в истории.
3. Если уверенности нет — просто переход по безопасному `href` к родителю. Не вызывать `history.back()` по одному `history.length>1`.
4. Не перехватывать `Ctrl/Cmd+click`, среднюю кнопку, `target=_blank`; `href` остаётся полноценным и доступным.
5. Если предыдущая страница — текущая или возможна петля перенаправлений, выбрать fallback.
6. Не записывать приватные данные/тексты заявок в sessionStorage. Допустимы только собственные адреса/состояния навигации.
7. Полноэкранный PDF: клавиша Escape / кнопка закрытия должна закрывать **просмотрщик**, а не сразу переводить на родителя. Не добавлять поверх viewer отдельный «Назад», не ломать фокусировку.

**Важное пожелание UX:** после возврата из узла в каталог ранее выбранная фильтрация должна сохраниться, а положение прокрутки браузер должен восстановить по возможности штатно; не прокручивать все каталоги автоматически в верх страницы.

### 4.4. Совместимость с существующими индикаторами

На сайте уже есть `.page-progress-rail` справа. Не накладывать на него возврат. Не превращать возврат в плавающий круг у правого края. Существующий `page-progress.js` не переписывать без необходимости. `scroll-margin-top` для якорных секций и `scroll-padding-top` должны учитывать суммарную высоту глобальной и локальной sticky-полос.

### 4.5. Реализация

Создай по возможности один переиспользуемый renderer, например `scripts/section-back-nav.mjs` или `scripts/context-navigation.mjs`, и отдельные минимальные JS/CSS (`public/context-navigation.js`, `public/context-navigation.css`) либо аккуратно встрои в уже используемую инфраструктуру, если так меньше дублирования. Подключай эти ассеты только к применимым маршрутам. Не делать три отдельных несовместимых «назад» на линиях, узлах и документах.

Важно: каталог узлов и каталоги линий уже могут иметь собственные breadcrumbs. Не дублировать навигационные цепочки: заменить/интегрировать старые с новой общей панелью, сохранив другие anchor-nav по разделам страницы.

## 5. Утверждённый стиль PDF-карточек: **Technical Archive** (никакие другие варианты)

### 5.1. Визуальная концепция

Нужно создать впечатление современного инженерного архива промышленного конструкторского бюро. Внутри карточки реальная первая страница PDF представлена как аккуратно экспонируемый технический документ. Подложка — холодная стально-серая, контрастирующая с основным тёплым цветом страниц ЭРА.

**Примерная палитра (доводи к существующим токенам):**

- основной стальной фон визуальной зоны: `#D8DEE5`;
- внутренняя более светлая грань / градиент: `#E4E8EC` / `#CDD5DE`;
- очень тонкие инженерные линии: `rgba(90, 110, 132, .35)`;
- подписи: глубокий индиго ЭРА (`var(--era-blue)`);
- золотой акцент — **очень дозированно** только для метаданных, активного состояния или микродетали;
- общий цвет карточки должен отличаться от кремового фона сайта, но не быть чёрным/синим.

Обложка остаётся настоящей: использовать существующий `/assets/document-covers/<id>.webp` из реестра (`d.cover`), а **не** генерировать фиктивные обложки, макеты с выдуманным текстом или заменять PDF. Не изменять оригинальные документы.

### 5.2. Характерная деталь — две тонкие линии над и под документом

На зоне просмотра обложки (`.dl-cover`) разместить **горизонтальные направляющие/риски**:

- сверху над титульной страницей — тонкая горизонтальная линия почти на ширину внутреннего поля;
- снизу — аналогичная;
- не пересекать буквы и графику титульной страницы;
- линии могут иметь очень короткие боковые/угловые засечки, как в инженерном чертеже;
- допустимо через `::before/::after`, фоновые градиенты или отдельные декоративные элементы `aria-hidden=true`;
- без перебора: НЕ чертить плотную миллиметровку и НЕ делать сложную сетку по всему сайту;
- не имитировать настоящий инженерный чертёж конкретного агрегата.

### 5.3. Пропорции обложек и высота карточек

- Обложку показывать целиком (`object-fit:contain`), не растягивать PDF до соотношения карточки и не обрезать A4/альбомные листы.
- Поддерживать горизонтальные обложки схем и чертежей: определить соотношение сторон из `coverWidth/coverHeight`, разрешить отдельный адаптивный вариант визуальной области, без расплывчатых огромных боковых полей.
- В существующем `.dl-cover` сейчас `height:275px; padding:20px; background:#ece7dd;` — именно этот фон заменить на Technical Archive и доработать декоративные линии. Высоту менять только если этого требует хороший просмотр и равная композиция соседних карточек.
- Обложка должна получить мягкую предметную тень, например с небольшим вертикальным смещением, без избыточного свечения.
- Около документа должно оставаться **осмысленное пространство**, организованное линиями и тональной структурой; не просто пустой фон.
- В листовом режиме `data-view=list` сохранить эстетически связанный фон и пропорции, не скрывать все направляющие / не деформировать титульную страницу.

### 5.4. Остальная часть карточки

- Сохраняем заголовок, объект, короткое описание, количество страниц, размер, ревизию/дату (если реально заполнены), связь с каталогом.
- Сохраняем `Открыть` / `Скачать PDF` и чекбокс «Выбрать» в режиме архива.
- Тонкий border, радиус в пределах уже принятой дизайн-системы, одинаковые высоты в строке, хорошие текстовые отступы.
- Предпочтительно очень светлая холодная нейтральная подложка под текстовой частью, слегка отличная от основного кремового фона, **но не плашка сплошного индиго**.
- Hover: очень небольшой подъём/усиление border/shadow; никакого масштабирования самого документа с обрезанием краёв. `focus-visible` доступный.
- «Документ по запросу»: сохранять честное визуальное состояние без фальшивого PDF. Можно адаптировать нейтральную подложку, но не рисовать обложку несуществующего файла.
- Состояние отсутствующей обложки: существующий `dl-cover-fallback` должен быть читабелен на стальном фоне.

### 5.5. Различные типы документов

Один **общий язык оформления** для всех пяти категорий:

- брошюры и презентации;
- технические описания;
- схемы и компоновки;
- чертежи и габариты;
- инвестиционные предложения.

Не менять цвет всей карточки под каждую категорию. Различия допускаются в неброском текстовом маркере типа документа и в ориентации обложки. Иначе библиотека визуально рассыплется на пять несвязанных дизайнов.

## 8. Новые документы: готовность к скорой публикации

Для пяти категорий сохраняем текущие `id` и публичные маршруты. Как только владелец предоставит схему, чертёж или инвестпредложение:

1. Проверить исходный PDF, метаданные (название, объект, версия, число страниц, размер).
2. Определить категорию (`layouts`, `drawings`, `investments`), тип объекта (`node`, `line`, `project`), существующий `objectSlug` и связанный маршрут; не путать `separatsiya-01` и `separatsiya-02`.
3. Подготовить запись в `additionalDocuments` / текущем утверждённом манифесте без дублирования уже известных PDF.
4. При необходимости выполнить `npm run documents:inspect`, `npm run documents:covers`, `npm run documents:validate` по принятому процессу.
5. Проверить, что обложка **реальная первая страница** PDF, а её пропорции корректно отражаются в Technical Archive (в т.ч. альбомный лист).
6. После публикации документ **автоматически** появляется в соответствующей категории и подборке объекта. Счётчик обновляется из реестра. Никаких ручных правок HTML ради каждой новой карточки.
7. Закрытые производственные чертежи не размещать в `public/`; `request-only` не должен выдавать прямой URL исходника.

В рамках **текущего** задания **не создавать фальшивых PDF, схем, чертежей и инвестиционных материалов** для заполнения пустых категорий. Структура и стили готовы к будущим реальным загрузкам.

## 9. Адаптивность

### Desktop (≥1200 px)

- главная витрина сохраняет крупные категории;
- внутренняя категория сразу показывает строку навигации и выдачу;
- три PDF-карточки в ряд, если позволяет ширина;
- sticky-панель не перекрывает верхнее меню, якоря, фильтры;
- стальная подложка PDF не превращается в массивный серый блок.

### Tablet (768–1199 px)

- две карточки в ряд;
- вкладки категорий горизонтально прокручиваются, если не помещаются;
- упрощённые breadcrumbs, но не только иконка без пояснения;
- фильтры переводятся в два столбца / адаптивную сетку.

### Mobile (320–767 px)

- один документ на строку;
- краткая внутренняя шапка, без декоративной второй колонки;
- шапка + sticky возврат без перекрытия viewport;
- вкладки в горизонтальной прокручиваемой полосе;
- документы и CTA должны читаться и нажиматься без масштабирования страницы;
- титульная страница целиком, мягкая стальная подложка, верхняя и нижняя линии сохраняются;
- модальный PDF-просмотрщик работает, кнопка закрытия видна.

Тестировать как минимум 360, 390, 768, 1280 и 1440 px; также низкую высоту окна (например, 720 px).
